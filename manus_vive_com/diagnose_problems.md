# MANUS Core 连接问题诊断指南

## 问题现象

用户报告：
1. C++客户端一直有东西滚动（正在运行并输出数据）
2. Python接收器显示"数据接收器线程已停止"
3. 连接异常: [WinError 10053] 你的主机中的软件中止了一个已建立的连接

## 可能原因

### 1. 端口冲突
- 可能已有其他Python接收器在运行
- 端口8888被其他程序占用

### 2. 连接超时
- C++客户端连接后立即断开
- Python接收器等待时间不足

### 3. 数据格式问题
- C++客户端发送的数据格式与Python接收器期望的不匹配
- JSON解析失败

### 4. 防火墙/网络问题
- Windows防火墙阻止了连接
- 本地回环地址(127.0.0.1)配置问题

## 诊断步骤

### 步骤1: 检查端口占用
```bash
# 在命令行中运行
netstat -ano | findstr :8888

# 如果看到类似输出，表示端口被占用
# TCP    127.0.0.1:8888         0.0.0.0:0              LISTENING       12345
```

### 步骤2: 运行连接测试
```bash
# 运行简单测试
python test_connection.py

# 或者运行快速测试
python simple_calibration.py test
```

### 步骤3: 检查C++客户端输出
1. 确保C++客户端正在运行
2. 检查C++客户端是否输出类似JSON的数据
3. 确认C++客户端连接到正确的端口(127.0.0.1:8888)

### 步骤4: 检查Python接收器
```bash
# 运行最简单的接收器测试
python -c "
import socket
s = socket.socket()
s.bind(('127.0.0.1', 8888))
s.listen(1)
print('等待连接...')
conn, addr = s.accept()
print(f'连接来自: {addr}')
data = conn.recv(1024)
print(f'收到数据: {data[:100]}...')
conn.close()
"
```

## 解决方案

### 方案A: 使用简单校准脚本
```bash
# 1. 确保没有其他Python程序在运行
# 2. 运行简单校准脚本
python simple_calibration.py
```

### 方案B: 修改端口
如果端口8888被占用，可以修改端口：

1. 修改C++客户端中的端口号
2. 修改Python接收器中的端口号：
   ```python
   # 在simple_calibration.py中修改
   receiver = ManusDataReceiver(host="127.0.0.1", port=9999)  # 改为其他端口
   ```

### 方案C: 检查C++客户端代码
确保C++客户端正确配置：
```cpp
// 在SDKMinimalClient_socket.cpp中
const std::string server_ip = "127.0.0.1";
const int server_port = 8888;  // 确保与Python端一致
```

## 快速修复

如果遇到连接问题，可以尝试：

1. **重启所有程序**：
   - 关闭所有Python脚本
   - 关闭C++客户端
   - 重新启动C++客户端
   - 重新启动Python接收器

2. **使用简化版本**：
   ```bash
   # 运行最简单的版本
   python simple_calibration.py
   ```

3. **检查数据格式**：
   - 确保C++客户端输出JSON格式数据
   - 每行应该是一个完整的JSON对象，以换行符结束

## 常见错误及解决

### 错误1: "端口被占用"
```
[TEST] 端口 8888 被占用
```
**解决**：关闭其他使用端口8888的程序，或修改端口号。

### 错误2: "连接超时"
```
[TEST] 连接超时 - C++客户端没有连接
```
**解决**：
1. 检查C++客户端是否正在运行
2. 检查C++客户端是否连接到127.0.0.1:8888
3. 检查防火墙设置

### 错误3: "JSON解析错误"
```
[ERROR] JSON解析错误: ...
```
**解决**：
1. 检查C++客户端输出的数据格式
2. 确保每行是一个完整的JSON对象

### 错误4: "WinError 10053"
```
[WARN] 连接异常: [WinError 10053] 你的主机中的软件中止了一个已建立的连接
```
**解决**：
1. C++客户端连接后立即断开
2. 可能是数据格式问题或网络问题
3. 尝试重启所有程序

## 成功运行的标志

当系统正常工作时，你应该看到：

1. **C++客户端**：持续输出JSON格式数据，包含骨架和Tracker数据
2. **Python接收器**：
   ```
   [OK] MANUS数据接收器启动在 127.0.0.1:8888
   等待C++客户端连接...
   [OK] 客户端已连接: ('127.0.0.1', 12345)
   [STATS] 已接收 100 帧 | FPS: 60.0 | 骨架: 1 | Tracker: 1 | ...
   ```
3. **Tracker数据**：Python端显示Tracker位置，不是None
4. **校准结果**：收集足够数据后显示校准建议

## 新增：Tracker数据诊断

如果Python端显示`[DEBUG] Tracker位置: None`，说明C++客户端没有发送Tracker数据。使用诊断工具检查：

```bash
python diagnose_tracker.py
```

这个工具会：
1. 分析C++客户端发送的数据类型
2. 显示骨架和Tracker数据的比例
3. 诊断可能的原因

### 常见Tracker问题

#### 问题1: "Tracker位置: None"
**症状**: Python端一直显示Tracker位置为None
**原因**: C++客户端没有发送Tracker数据
**解决**:
1. 确保MANUS Core中配置了Vive Tracker设备
2. 检查C++客户端是否编译了Tracker支持
3. 运行`diagnose_tracker.py`确认数据流

#### 问题2: "连接异常: [WinError 10053]"
**症状**: 按下't'或'r'后连接断开
**原因**: 输入阻塞导致socket问题
**解决**:
1. 使用最新的`debug_demo.py`（已修复非阻塞输入）
2. 确保C++客户端持续运行

#### 问题3: "平移质量检测不准确"
**症状**: 用户移动直线但系统检测为"一般"或"需要改进"
**原因**: 算法阈值太严格或数据噪声
**解决**:
1. 已降低线性度阈值从0.95到0.90
2. 确保Tracker数据稳定
