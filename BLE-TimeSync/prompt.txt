Windows → ESP32 请求协议：
- 固定 12 字节
- 小端序
- uint64 sec
- uint32 usec
- Python struct 格式：<QI
- sec/usec 来自 Windows Unix Epoch 时间
- 使用 write-with-response，即 Bleak write_gatt_char(..., response=True)

ESP32 → Windows 响应协议：
- 固定 32 字节
- 小端序
- Python struct 格式：<QqQQ

字段：
1. uint64 phone_us
2. int64 offset_us
3. uint64 esp_receive_us
4. uint64 esp_process_us

时间逻辑：
- Windows 绝对 Unix 时间用 time.time_ns()
- RTT 测量必须使用 time.perf_counter_ns()
- 不要用系统墙上时间计算 RTT
- T1 在发起 GATT write 前尽可能晚地记录
- T4 在 Notify callback 中尽可能早地记录
- ESP 处理时间：
  esp_processing_us = esp_process_us - esp_receive_us
- 净 RTT：
  net_rtt_ms = total_rtt_ms - esp_processing_ms
- 单向延迟：
  one_way_ms = max(net_rtt_ms / 2, 0)

校准逻辑：
- 默认 5 次
- 每次间隔 500 ms
- 校准阶段不加补偿
- 同时计算：
  1. 小程序兼容值：平均 total RTT / 2
  2. 推荐值：net RTT 单向延迟的中位数
- 默认使用 net RTT 单向延迟中位数作为 compensation
- 校准结束后默认每 10 秒授时一次
- 发送目标时间：
  当前 Windows Unix 时间 + compensation
- 保持 BLE 长连接，不要每次重新扫描和连接

必须实现的 CLI：

python -m app.main scan

README 必须说明现场运行顺序：
1. 关闭手机授时小程序。
2. 确保手机没有连接 ESP32S3-TimeSync。
3. 重启 ESP32。

5. Windows 执行 python -m app.main run。
6. 等待 5 次校准完成。
7. 确认 Windows 持续收到 Notify。
8. 确认 NanoPi 持续收到 UART TIMESYNC。
