BLE-TimeSync v3 当前工程约束

1. 本工程只负责 Windows 自身 BLE 连接 Slave 68/69/70 并进行 UTC 授时。
2. 三台 Slave BLE 名称必须严格为 68、69、70。
3. Windows 只使用 Time Sync (...9abd) 和 Time Status (...9abe)。
4. Windows 不写 Pulse Control (...9ac1)，也不再使用旧 Control (...9abf) / Gateway Status (...9ac0) 做采集控制。
5. START / TICK / STOP 由独立 Master ESP32 通过 BLE 下发给三台 Slave。
6. Windows 通过独立 Master-Serial-Control 工程，以 USB Serial 115200 8N1 向 Master 发送 START / STOP / STATUS。
7. 每台 Slave 必须同时保持 Master 与 Windows 两条 BLE 连接；第一条连接建立后继续广播直到连接数达到 2。
8. Windows 与每台 Slave 建连后完成首次 UTC 授时，之后默认每 30 秒授时一次；三台写入默认错开 300 ms。
9. BLE-TimeSync 不负责相机 30 Hz GPIO2，也不负责 Slave UART START/STOP；这些属于 Master/Slave 固件职责。
10. 旧 app/gateway_protocol.py 与对应旧测试已删除，不恢复旧 Windows BLE START/STOP 控制链。
11. capture_ui 已接入 Master-Serial-Control；启动 BLE 授时时，Master-Serial-Control 与 BLE-TimeSync 必须并行启动，不能等待 Master 三台全 READY 后才启动 Windows BLE。
12. capture_ui 只有在 Master 侧 68/69/70 全部 CONNECTED 且 BLE-TimeSync 三台都完成首次授时后，才允许正式开始采集。
13. UI 的采集 1/0 只发送给 Master-Serial-Control；BLE-TimeSync 的 --control-stdin 只处理 quit/exit。
14. 当前已用 Master + Slave69 实机验证双 BLE、首次授时、30 秒周期授时及 UI 并行启动；68/70 尚无硬件，三机 START/TICK/STOP 待后续最终验收。
